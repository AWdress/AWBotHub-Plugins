# 系统助手：从第一次提问到排查问题

系统助手可以查询运行状态、分析日志、查看插件任务，按需调用插件按钮，或在确认后修改非敏感配置。它使用「系统设置 → AI 服务」中的模型，不需要安装一个同名插件。

本文按 v2.0.2.7 的界面和能力编写。建议先完成第 1 节，只用查询功能；熟悉操作预览后，再打开修改权限。

![系统助手](https://raw.githubusercontent.com/wiki/AWdress/AWBotNest/images/assistant.jpg)

## 1. 第一次使用：先让助手查一次状态

### 第一步：配置文字模型

1. 打开「系统设置 → AI 服务」。
2. 添加服务商，将供应商提供的真实模型加入「模型库」，勾选「文字模型」。
3. 在「模型分工 → 文字模型 → 默认模型」选择它，保存后点击「测试」。
4. 基础接入成功后，点击 AI 服务页的「打开系统助手」，也可以从网页顶部进入。

完整配置步骤见 [AI 服务](AI-Service)。**助手使用的文字模型还必须支持工具调用**：普通问答测试成功，只证明能聊天，不代表供应商接受助手的工具参数。

系统支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages。供应商提供了模型，不代表它开放了该模型的所有协议或工具能力。

### 第二步：检查助手设置

打开助手的「设置」页签：

- 保持「启用助手」打开。
- 「模型」可保持「使用系统默认文字模型」，也可以单独选择一个模型。
- 首次使用先不要打开「允许执行修改操作」。
- 点击「保存设置」。

### 第三步：发送一个明确的问题

回到「对话」，输入：

```text
检查系统运行状态和最近的错误日志。先告诉我确定的问题，不要修改任何配置。
```

正常时，会看到执行步骤和回复。助手应根据实际查询结果回答；不要把模型的一句“已完成”当成操作成功，修改、执行插件按钮等结果还应核对对应页面或日志。

### 这些要求比较容易得到有用的结果

```text
检查“某插件”当前有没有定时任务，下次运行是什么时间，最近一次有没有报错。
```

```text
这个插件刚才没运行。先查任务状态和相关日志，区分没有触发、排队和执行失败。
```

```text
比较这个插件当前的公开配置和配置说明。只列出疑似填错的地方，先不要保存。
```

问题中写清插件名称、发生时间、预期结果和实际现象，比只说“坏了”更容易排查。不要把密码、Cookie、Token 或 Session 发给助手。

## 2. 对话窗口怎么用？

助手有「对话」「预约」「记忆」「技能」「设置」五个页签。

| 位置 | 用途 |
| --- | --- |
| 会话标题 / 历史入口 | 搜索和切换以前的会话 |
| 新建会话 | 换一个问题，避免把无关背景带进来 |
| 执行步骤 | 查看正在读取、分析、等待还是执行 |
| 输入框 | 发送问题；任务执行时可以补充文字要求 |
| 添加图片 / 附件 / 录音 | 提交截图、文本资料或语音 |
| 技能入口，或输入 `/` | 选择一个可用技能，再补充具体要求 |
| 停止 | 停止当前任务；不会撤销已经完成的操作 |

桌面端可全屏显示，手机端使用全屏面板。关闭助手窗口不会停止任务，重新打开还能继续查看。需要中止时应点击「停止」，而不是只关闭窗口。

同一个会话只能执行一个任务。执行中可以补充文字，附件请等当前任务结束后再发。缺少信息时，助手会暂停提问；选择答案只是补充信息，**不等于批准修改**。

会话保存在 `data/assistant.db`。较早内容会整理为摘要，记录也有保留上限，不能把助手会话当作永久档案。备份系统数据时，应一并保留该文件；不要在系统运行时只复制某个 SQLite 文件来代替完整备份流程。

## 3. 助手能改什么？要怎么批准？

默认是只读模式。确认需要它执行操作后，在「设置」打开「允许执行修改操作」并保存。

此开关不是永久授权。写入类操作仍会先显示「需要管理员确认」，列出这一次的目标和参数，由管理员点击「确认执行」或「拒绝」。不能用“以后都同意”跳过后续确认。

### 修改系统或插件配置

例如：

```text
把“某插件”的定时规则改成每天上午 9 点。先确认实际字段，列出修改前后的值，再让我确认。
```

助手会先读取允许公开的字段，校验值，再生成预览。确认时重点看：

1. 是否是正确的插件或系统设置。
2. 是否只修改你要求的字段。
3. 「修改前」「修改后」是否正确。
4. 保存后是否立即生效，还是需要另行重载或重启。

系统设置只开放工具目录中列出的部分字段；插件配置也以实际返回的字段为准。助手不能随意改一切文件或未声明的业务数据。

### 调用插件里的按钮

可以要求“查看这个插件有哪些可执行按钮”，再要求执行其中一个。系统支持已注册的插件动作，也兼容旧的 `ctx.action(name, callback)` 按钮，不要求这些按钮为助手单独改造。

但不是界面上所有按钮都必然能执行：只存在于自定义页面、通过插件自定义 API 或 Webhook 处理、没有注册成系统动作的按钮，不会被当成任意接口调用。未声明参数的旧按钮只支持空参数执行。

助手也可在确认后启用、停用或重新加载已安装插件。停用和重载可能中断正在执行的任务，确认前要注意。

### 明确不开放的内容

- 密钥、密码、Cookie、Token、验证码、Telegram Session、认证和权限配置，不能交给助手读取原值、修改或清空。
- 环境变量、代理、凭据去向相关的服务地址、请求头或执行路径，不通过助手任意修改。
- 含敏感子项的数据，不会为方便而整组开放。支持的公开子字段可以单独修改，不能用替换整个账号列表的方式覆盖密码。
- 主系统不提供任意 Shell、Python 执行或任意文件读取。独立沙箱是另一项可选功能，见第 10 节。

确认通常 15 分钟内有效，只能用一次。等待期间配置、插件运行状态或来源发生变化时，需要重新核对；过期后重新发起任务，不能继续点旧按钮。拒绝后，助手不能换一组参数绕过同一项拒绝。

## 4. 发截图、文本文件和语音

### 图片：需要视觉模型

1. 在「系统设置 → AI 服务 → 模型库」为真正支持识图的模型勾选「视觉模型」。
2. 在「模型分工 → 视觉模型」选择默认模型并保存。
3. 在助手点击添加图片，或直接粘贴截图，再说明要检查哪里。

例如：“截图中保存时出现这个错误，请结合系统日志判断原因，不要先改设置。”

一次最多 3 张图片，单张不超过 5 MiB，合计不超过 8 MiB。图片先经过识别，再结合文字要求处理；截图中的指令、链接或“已批准”不能代替管理员确认。纯文字模型不会因为勾选视觉能力就自动获得识图能力。

### 文本附件：发必要片段，不要发整份凭据文件

支持 UTF-8 编码的 TXT、Markdown、JSON、CSV、TSV、YAML、TOML、INI 和日志文件。一次最多 3 个，文本合计不超过 10000 字节。

附件只是分析资料，不会自动执行里面的代码。不要上传 `config.json`、`auth.json`、Session、Cookie 导出、私钥或包含密钥的完整日志；排错时先删去凭据，只发必要片段。

### 语音：需要语音转写模型

1. 添加支持 OpenAI `/audio/transcriptions` 接口的服务和模型。
2. 在「模型库」勾选「语音转写」。
3. 在「模型分工 → 语音转写」选择默认模型并保存。
4. 在助手录音或添加音频，先用一条简短语音验证。

单条语音最多 8 MiB。支持上传 WAV、MP3、M4A、MP4、WebM、Ogg、AAC、AMR 等格式，但**供应商也必须接受该格式**。Telegram 常见 Ogg、企微常见 AMR 是否能转写，取决于服务商；失败时改发文字或供应商支持的音频，不要只修改扩展名。系统不会自行转码，也不能用普通文字模型代替转写服务。

网页单次请求总上限为 12 MiB，同时提交多类附件仍须满足总上限。原始图片和语音不写入会话数据库，识别和转写后的脱敏文字会用于对话；文本附件保存脱敏文本。附件会发送给你配置的 AI 服务，上传前仍须考虑隐私。

浏览器录音还需要麦克风权限和浏览器支持的安全访问环境。通过普通公网 HTTP 打开而无法录音时，可改用 HTTPS，或上传已经录好的音频文件。

## 5. 在 Telegram Bot 使用助手

先在系统中配置好一个 Bot，确认它能正常启动、收发消息。Bot 的普通消息权限与助手权限是两回事：**进入 Bot 白名单不会自动成为助手管理员**。

### 配对步骤

1. 网页打开「系统助手 → 设置 → 消息渠道」。
2. 「渠道类型」选择 Telegram，选择要使用的 Bot。
3. 点击「生成配对码」。
4. 在 10 分钟内，由你本人私聊这个 Bot，发送网页给出的完整命令，例如 `/配对 页面显示的代码`。
5. 回网页点击「已发送，刷新配对结果」，确认出现自己的绑定记录。

配对码只能使用一次，不要截给别人。只能到选中的 Bot 配对，不是发给任意一个 Bot 都有效。

配对成功后已进入助手模式，也可用 `/助手 你的要求` 进入。后续直接发文字、图片、文本文件或语音即可。

| 命令 | 用途 |
| --- | --- |
| `/助手 检查系统状态` | 进入助手模式并提出要求 |
| `/新会话` | 换一个新的对话；当前仍有任务时先停止 |
| `/停止` | 停止当前任务 |
| `/退出助手` | 退出助手模式，普通消息恢复原来的插件处理 |

修改预览下方会显示「确认执行 / 拒绝」按钮，需要选择时显示选项按钮。确认和选择不使用文字口令，只能由对应的已配对管理员点击。Telegram 群消息不会因此获得助手权限。

Bot 运行时可以显示原生「正在输入」，不会每条消息都回复“已收到，正在处理”。看到等待确认时，应查看上一条操作预览和按钮，而不是反复发送相同要求。

## 6. 在企业微信使用助手

企微的前提比普通推送多一步：**既能发通知，又要配置好加密回调，才能把消息送回系统**。只有 Webhook 推送、没有可用自建应用回调的渠道，不是双向助手入口。

1. 先按 [账号与通知](Accounts-and-Notifications) 配好企业微信自建应用、回调 Token、AESKey 和成员白名单，确认回调验证成功。
2. 打开「系统助手 → 设置 → 消息渠道」，选择企业微信及对应应用。
3. 点击「生成配对码」。在 10 分钟内向这个应用发送网页显示的 `/配对 代码`。
4. 回网页刷新，确认绑定的是自己的企业微信成员账号。
5. 发送 `/助手 你的要求`，后续可用文字、图片、文本文件或语音继续对话。

普通成员白名单不是助手授权，仍需单独配对。撤销某人的助手权限时，在网页绑定记录中撤销配对；旧按钮和排队任务随之失效。

企业微信使用原生交互卡片进行确认和选择。这里指企业微信自建应用的客户端入口；普通微信、微工作台等不支持交互卡片的入口，请到网页处理，不能改发“确认”来代替按钮。

若渠道下拉框没有企微应用，先检查：应用是否启用、是否打开回调、回调必填项是否完整，不要只检查它能否向你发送一条通知。

Bot 自动重连后会恢复助手入口，不需要反复配对。短暂断线时，尚未提交的消息和尚未发送的结果最多等待恢复 60 秒；发送结果不确定时不会盲目重发。发生超时后应先看会话记录和实际执行结果，再决定是否重新请求。

## 7. 记忆和内置技能

### 记忆：保存你的偏好

在「记忆」页填写一条常用偏好，点击「保存记忆」。例如：

```text
检查结果用中文，先列异常，再列建议；没有证据时说明还不能确定。
```

也可以要求助手提出一条记忆，批准后保存。「设置 → 使用已保存的记忆」关闭后，不再给模型提供这些偏好。记忆不是自动执行授权，更不要用来保存密钥。

### 技能：保存一套处理步骤

在对话输入 `/`，或打开「技能」页查看可用技能。技能是办事方法，不是单独运行的程序，也不会扩大助手权限。

系统有 7 项内置技能：

| 技能名 | 适合什么问题 |
| --- | --- |
| `awbotnest-api` | 查系统、插件、任务、公开配置和近期日志 |
| `command-dispatch` | 查找并调用实际注册的插件按钮 |
| `config-management` | 检查并修改允许开放的配置 |
| `feedback-issue` | 整理脱敏问题报告并准备 GitHub Issue |
| `source-repair` | 查看源码、准备精确补丁并说明生效方式 |
| `create-awbotnest-skill` | 把常用流程整理为自定义技能 |
| `awbotnest-update` | 读取已有的系统更新检查结果；不会安装或重启 |

内置技能可以查看步骤，但不能修改或删除。自定义技能在「技能 → 添加自定义技能」填写「名称」「用途」「处理步骤」后保存，可以编辑或删除，最多 50 项。

技能按需读取，不会把所有内容塞进每次对话。系统参考了 MP V3 的 Skill 组织方式，但不是照搬 MP 的运行环境；MP 的媒体搜索、下载、订阅和整理业务，仍需要本系统对应插件实际提供动作。

## 8. 预约一次检查，或每天定时检查

打开「预约」页，填写「任务名称」「任务要求」和「执行方式」：

- 「指定时间」按界面显示的**本地时间**选择日期和时间。
- 「重复执行（北京时间）」使用五段 Cron，时区固定为 `Asia/Shanghai`。

例如 Cron `0 9 * * *` 表示每天北京时间上午 9 点，任务要求可以写：

```text
检查昨天“某插件”的定时任务和错误日志，只报告异常，不修改配置。
```

点击「添加预约」。也可以在对话中说“明天上午九点检查某插件运行情况”，由助手提出预约，再审阅时间并确认。

每个周期至少间隔 5 分钟，最多保存 32 个预约。到时会创建新会话；忙碌时排队，不会因为没有执行名额就直接丢弃。同一个预约未结束时不重叠启动，积压的 Cron 触发会合并补跑一次。

**预约不等于长期批准修改。** 到时需要写操作，仍会停在确认步骤，过期不执行。暂停或删除预约不取消已经开始的任务，需进入对应会话停止。

希望接收结果时，打开「设置 → 预约通知」并保存；默认关闭，打开后通过默认 Bot 发送结果或待确认提醒。默认 Bot 必须已配置且可用。

系统重启后，已经开始却未完成的助手任务会标为已中断，不会自动重放结果不明的写操作；尚未开始而已到期的预约会补跑一次。

## 9. 查看源码、准备修复和提交 Issue

### 先查原因，再准备补丁

可以提出：

```text
检查“某插件”的这条报错。先查看日志和相关源码，说明原因；需要修改时先给我差异，不要直接运行候选代码。
```

助手能列出、搜索和按行读取允许范围内的文本源码。插件仅限已安装插件自身；系统源码仅限受支持的 `awbotnest/` 和 `frontend/src/` 文件，数据、Session、依赖和任意目录不开放。

| 部署方式 / 文件 | 实际能做什么 |
| --- | --- |
| 源码部署，允许修改的文本文件 | 准备单文件精确差异，确认后保存 |
| 认证、敏感值处理、助手安全相关源码 | 只准备补丁供审查，不能由助手直接保存 |
| 编译后的 Docker 核心 | 不能直接修改二进制；有可信构建清单时，可核对官方对应提交源码，准备参考补丁或 Issue |
| Docker 中的插件源码 | 不受核心编译影响，但仍受范围、校验和确认约束 |

旧镜像缺少可信源码清单时，助手会说明无法核实，不会拿同名版本标签猜文件内容。

准备补丁不代表已保存，保存也不代表已经生效。Python 仅做语法检查，不导入或运行候选代码；其他语言未运行验证时，不能算测试通过。保存不自动重载插件、重启系统或构建前端，需要这些步骤时另行操作和确认。

保存前会备份到 `data/source_backups`；累计达到 64 份或 32 MiB 时暂停新保存，需要管理员整理。备份不自动删除，可能包含源码原有的敏感内容，不要公开。商店更新可能覆盖插件本地修改，长期修复应反馈作者。

### 提交 GitHub Issue

1. 在「系统设置 → 运行环境」的「运行代理」卡片中找到「GitHub Token」，填写并保存。提交 Issue 需要目标仓库的 Issue 写入权限，仅有查询配额的 Token 不一定够用；建议只授权必要仓库。
2. 在助手「设置」打开「允许执行修改操作」和「允许提交 GitHub Issue」，保存。
3. 明确告诉助手“为这个问题整理并提交 Issue”。
4. 检查确认卡中的**目标仓库、标题、完整正文**，确认无凭据和个人隐私，再点「确认执行」。

系统问题提交到 `AWdress/AWBotNest`；插件问题按已安装插件的可信来源识别作者仓库，不需要手填仓库。手动上传、来源不明或记录不完整时，只整理报告，不猜作者。

没配置 Token 或没打开提交权限，也可以让助手生成报告，之后自己复制到 GitHub。源码修复的确认与公开 Issue 的确认是两回事，不能用批准补丁代替批准公开。

Issue 通常公开可见。系统会脱敏已知凭据，但不能识别所有未知秘密，管理员仍须逐项审阅。不会自动上传整份配置、私有源码、截图或完整日志。提交超时、重启或结果不明时不要反复点击，先到 GitHub 核对是否已经创建，避免重复。

## 10. 可选：网页搜索、MCP 和独立沙箱

这些功能默认关闭，普通状态查询和配置排错不必全部开启。

### 公开网页搜索和阅读

在「设置」打开「允许网页搜索和阅读」并保存，可要求助手检索公开资料，或读取指定公开网页。

这不是浏览器自动操作：不登录、不执行 JavaScript、不读取 Cookie，不访问内网，也不下载文件。动态页面、登录后内容或搜索服务不可用时，可能无法读取，需要提供公开静态链接或必要文本。

面对可以分开查询的问题，助手还可使用最多两个只读子助手分别检查，再汇总结果。子助手不能修改配置、预约、提交 Issue 或继续派生助手；与主任务共用执行名额和用量统计，不是另一组无限资源。

### 外部工具（MCP）

1. 先确认服务来源可信，再打开「允许使用外部工具（MCP）」并保存。
2. 展开「外部工具（MCP）」，点击「添加服务」。
3. 填「服务名称」「服务地址」，需要认证时填专用 Token；带 Token 必须使用 HTTPS。
4. 首次可将「只读工具名称」留空，保持每次调用都要确认。
5. 保存后点击「连接并读取工具」，检查实际工具目录。

最多 4 个公网 HTTP(S) MCP 服务，不接受本机、内网、stdio 或可执行命令。只有管理员明确填写为只读的工具可直接查询，不会仅凭外部服务自称“只读”就免确认。更换地址、凭据或工具定义后，旧确认失效。外部工具收到的请求和返回结果也可能涉及隐私，勿随便连接陌生服务。

### 独立沙箱：不是在系统容器里执行任意代码

需要代码计算、临时文件或浏览器交互时，可额外部署独立执行服务。助手设置里填一个地址，**并不会自动部署服务**。

沙箱由独立 broker 按会话创建执行容器，使用非 root、只读根目录、临时工作目录及资源上限；不挂载系统配置、插件、Session 或 Docker socket。代码运行、文件读写和浏览器操作每次仍需确认。

操作顺序：

1. 准备可信 Linux Docker 主机和与当前系统对应的源码。
2. 按 [独立助手沙箱部署说明](https://github.com/AWdress/AWBotNest/blob/v2.0.2.7/docs/ASSISTANT_SANDBOX.md) 生成专用随机 Token，构建 runner 和 broker，只常驻启动 broker。
3. 打开「系统助手 → 设置 → 独立沙箱」，填写「沙箱服务地址」「沙箱 Token」，启用后点击「保存沙箱配置」。同一 Compose 网络的示例地址为 `http://assistant-sandbox:8765`；不同网络不能直接照填。
4. 点击「检查沙箱连接」。保存成功和连接正常是两个不同结果。
5. 开启助手修改权限后，先要求“在沙箱用 Python 计算 6×7”，核对确认内容和返回值，再尝试实际需求。

broker 管理 Docker 容器，属于高权限受信服务；不要公开暴露，不要把 Docker socket 挂给主系统。运行不可信代码时更建议独立主机，不应为方便开启特权模式或挂载宿主目录。

沙箱文件是临时的，不能当备份。改了沙箱文件，不等于改了已安装插件或系统源码；它也不能绕过配置工具直接改系统设置。浏览器只访问受校验的公网 HTTP(S)，不能访问本机、内网、云元数据或任意端口，不提供附件下载。

## 11. 为什么没有执行？按这个顺序看

| 现象 | 优先检查 |
| --- | --- |
| 连普通查询都失败 | AI 服务是否保存；文字模型是否启用；供应商是否支持工具调用；最近调用记录中的实际错误 |
| 能回答但不能改配置 | 「允许执行修改操作」是否打开并保存；字段是否属于支持范围；是否正等待管理员确认 |
| 找不到某插件按钮 | 插件是否已安装、加载成功；按钮是否注册为系统动作；自定义页面按钮不一定支持 |
| 点击确认失效 | 是否超过 15 分钟；配置、插件、权限或来源是否在等待期间改变；重新发起并核对新预览 |
| 图片不能识别 | 是否配置默认视觉模型；服务商是否真正支持图片；附件尺寸是否超限 |
| 语音不能转写 | 是否设置默认语音转写模型；是否支持 OpenAI 音频接口；是否接受 Ogg/AMR 等实际格式 |
| 手机录音不可用 | 麦克风权限、安全访问环境和浏览器支持；可改为上传音频 |
| Bot / 企微没有响应 | 渠道是否在线、企微回调是否正常；是否本人已配对；是否进入助手模式；看网页会话状态 |
| Telegram 群里不能用 | 助手入口仅面向已配对管理员的私聊，不把群权限当管理员权限 |
| 企微能收通知但不能聊天 | 检查自建应用加密回调和成员白名单，推送成功不能证明回调可用 |
| 等待很久 | 执行步骤是否在排队、等模型、等外部工具或等确认；不要连续新建相同任务 |
| 预约到了却没有改设置 | 写操作仍需本次确认；打开预约对应会话查看，不是自动长期授权 |
| Docker 核心只给补丁 | 编译核心无法原地改写，这是部署边界；应审查补丁后更新源码或镜像 |
| 已保存源码但行为没变化 | 保存不自动生效，核对是否需插件重载、前端构建或系统重启 |
| Issue 没发出去 | 检查两项权限和 Token 的目标仓库权限；超时先核对 GitHub，避免重复提交 |

系统不设置任务累计 Token、执行轮数或工具调用次数额度；这不等于服务商免费或系统资源无限。仍有单次超时、活动任务名额、附件大小和历史保留限制。默认单次模型调用超时为 120 秒，可在「设置 → 请求设置」调整；长时间重复查询没有新结果时会停止。

最多接收 8 个活动任务，同时执行 2 个助手步骤，等待确认不会占用这两个步骤名额。会话、执行记录、记忆等也会按保留上限整理；Token 用量没有服务商精确返回时显示估算，最终费用以服务商账单为准。

当前最多保留 100 个会话、每会话 80 条消息、200 次执行记录、100 条记忆、50 项自定义技能和 20 份反馈草稿。活动任务会保留到结束，较长会话还可能按大小整理早期内容。需要长期留存的排查结论应自行另存；不要把历史保留条数误认为任务只能执行这些次数。
